# ft_kalman

`ft_kalman.pdf`의 요구사항에 따라, 잡음이 포함된 IMU/GPS 데이터로 3차원 위치를 추정하는 칼만 필터를 C++17로 구현하는 프로젝트다.

이 문서는 프로젝트 설명서이자 작업 현황판이다. 작업을 마칠 때마다 해당 체크박스를 갱신하고, 검증 결과나 프로토콜 관련 결정 사항을 아래 기록에 남긴다.

## 최종 목표

`imu-sensor-stream-macos`와 UDP로 통신하면서 다음 과정을 종료 시점까지 안정적으로 반복한다.

1. 센서 스트림에 `READY` 핸드셰이크를 보낸다.
2. 초기 위치와 초기 속도로 필터를 초기화한다.
3. 가속도와 방향을 이용해 현재 위치를 예측한다.
4. GPS가 들어오면 측정값으로 예측을 보정한다.
5. 매 입력마다 1초 이내에 추정 위치를 `X Y Z` 형식으로 보낸다.
6. 최대 90분짜리 기본 잡음 궤적에서도 실제 위치와의 오차를 5 m 이내로 유지한다.

## 과제 요구사항 요약

- 언어: C, C++ 또는 Rust. 이 저장소는 C++17을 사용한다.
- 필터: 직접 구현한 칼만 필터를 사용해야 한다.
- 센서 입력:
  - 시작 시 실제 초기 위치 `(X, Y, Z)`, 단위 `m`
  - 시작 시 실제 초기 속력, 단위 `km/h`
  - 0.01초마다 가속도 `(X, Y, Z)`, 단위 `m/s^2`
  - 현재 방향을 나타내는 오일러 각
  - 3초마다 GPS 위치 `(X, Y, Z)`, 단위 `m`
- 기본 백색 가우시안 잡음:
  - 가속도계: `sigma = 1e-3`, `mu = 0`
  - 자이로스코프: `sigma = 1e-2`, `mu = 0`
  - GPS: `sigma = 1e-1`, `mu = 0`
- 빌드 시 `-Wall -Wextra -Werror`를 사용하고 불필요하게 재링크하지 않아야 한다.
- 타임아웃, 잘못된 입력 및 큰 추정 오차를 충돌 없이 처리해야 한다.

원문은 [`ft_kalman.pdf`](ft_kalman.pdf)를 참고한다.

## 통신 프로토콜

### 연결과 핸드셰이크

기본 서버 주소는 다음과 같다.

```text
host: 127.0.0.1
port: 4242
transport: UDP
```

센서 스트림을 먼저 실행한 뒤 클라이언트를 실행한다. 클라이언트는 다음 문자열을 전송해 궤적 생성을 시작한다.

```text
READY
```

현재 코드는 `READY\n`을 보내며, 실제 센서 스트림이 이를 정상적으로 받아들이는 것을 확인했다.

### 수신 메시지

센서 데이터 한 묶음은 다음 마커로 감싸진 텍스트다. 실제 스트림은 마커, 레이블, 각 숫자를 각각 별도의 UDP 데이터그램으로 전송하므로 `MessageAssembler`가 데이터그램 사이의 줄 경계를 복원한다.

```text
MSG_START
...
MSG_END
```

각 필드는 시간 레이블 다음 줄들에 숫자가 배치되는 형식으로 보인다. 제공된 바이너리 문자열과 현재 파서를 기준으로 확인된 레이블은 다음과 같다.

| 레이블 | 의미 | 값 |
|---|---|---|
| `TRUE POSITION` | 초기 실제 위치 또는 디버그용 실제 위치 | 숫자 3개 |
| `SPEED` | 초기 속력 | 숫자 1개 |
| `ACCELERATION` | 가속도 | 숫자 3개 |
| `DIRECTION` | 오일러 각 | 숫자 3개 |
| `POSITION` | 잡음이 포함된 GPS 위치 | 숫자 3개 |

> 디버그 모드에서는 매 시점의 `TRUE POSITION`과 `SPEED`도 함께 전송된다. 일반 모드에서는 GPS 시점에 `POSITION`이 추가된다.

파서는 `\n`과 `\r\n`을 모두 허용하고, 알 수 없는 필드는 무시하되 알려진 필드의 값 개수나 숫자 형식이 잘못되면 명확한 오류를 반환해야 한다.

### 위치 응답

각 입력을 처리한 뒤 다음 형식으로 위치를 보낸다.

```text
1.7325073314060224 -2.2213777837034083 0.49999962025821726
```

규칙은 다음과 같다.

- 공백으로 구분된 유한한 실수 3개
- 순서: `X Y Z`
- 센서 스트림의 응답 제한 시간 1초 이내
- 실제 위치와의 거리 5 m 이내
- 서버가 다음 데이터를 보내기 전에 위치 응답을 기다리므로, 입력 하나당 응답 하나를 보낸다.

## 권장 구조

필터의 상태 벡터는 위치와 속도를 함께 추정하는 6차원 벡터로 시작한다.

```text
x = [px, py, pz, vx, vy, vz]^T
```

가속도 `a = [ax, ay, az]^T`와 실제 메시지 간격 `dt`를 제어 입력으로 사용한다.

```text
p(k+1) = p(k) + v(k) * dt + 0.5 * a(k) * dt^2
v(k+1) = v(k) + a(k) * dt
```

GPS가 없는 입력에서는 예측만 수행하고, `POSITION`이 포함된 입력에서만 GPS 측정 갱신을 수행한다. 먼저 이 최소 모델을 완성한 뒤, 실제 데이터에서 필요성이 확인될 때만 방향 또는 가속도 바이어스를 상태에 추가한다.

권장 책임 분리는 다음과 같다.

| 구성 요소 | 책임 |
|---|---|
| `UDPClient` | UDP 송수신과 수신 타임아웃 |
| `MessageAssembler` | 임의의 청크에서 완전한 메시지 0개 이상 추출 |
| `Parser` | 텍스트 메시지를 단위가 명시된 `SensorUpdate`로 변환 |
| `SensorState` | 입력 순서, 시간 차이, 필터 초기화 여부 관리 |
| `KalmanFilter` | 상태/공분산 예측과 GPS 측정 갱신 |
| `main` | 핸드셰이크와 요청-응답 루프, 오류 보고 |

## 빌드와 실행

### 빌드

```sh
make
```

생성 파일은 `./kalman`이다.

```sh
make clean   # 오브젝트 파일 삭제
make fclean  # 오브젝트와 실행 파일 삭제
make re      # 전체 재빌드
```

### 실행 순서

PDF에 제시된 센서 스트림 실행 예시는 다음과 같다.

```sh
./imu-sensor-stream-macos -s 42 -d 42 -p 4242
```

별도 터미널에서 필터를 실행한다.

```sh
./kalman
```

Apple Silicon에서는 Rosetta를 통해 실행한다.

```sh
arch -x86_64 ./imu-sensor-stream-macos -s 42 -d 1 -p 4242 --filterspeed
```

`-s`는 seed, `-d`는 분 단위 duration, `-p`는 UDP 포트다. 현재 클라이언트의 포트는 `4242`로 고정되어 있다.
